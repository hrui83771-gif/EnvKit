## 一、预案库

一次处置做完，步骤序列可以**存成预案**（终态行动卡片上的「存为预案」）。下次同类故障不再是空白对话：

- **匹配是结构化的**：服务 / 错误类型 / 触发来源三组 AND 门槛 + 标题关键词加分。四项全空的预案**永不匹配**——否则它会吞掉所有告警，而用户看不出为什么。
- **排序确定**：分数 → 成功率 → ID 字典序。同一个故障点两次，给出的建议必须一模一样；说不清的推荐等于不可审计的推荐。
- **连败 3 次自动进「待复审」**，不再推荐。不直接停用：连败可能是环境变了，不是预案错了。
- 成功只认复验通过。执行完没验过一律记失败——宁可低估，不发假徽章。

## 二、告警闭环

守护（guard）接不住的事件——「拉起来了但复验没过」「恢复失败」——会升级成待批行动，并**当场套上匹配的预案**、把步骤预填成「起草步骤」。

这部分刻意与「已执行步骤」分成两个字段（`Draft` / `Plan`）：混在一起会让「步骤数」和「续作回放点」两个语义同时失真。

套预案只省「推理怎么修」，**不省确认**。每个写步骤照常弹确认卡——这条没有开关。

## 三、晨报

按设置里的时刻（默认 08:30）产出一份只读报告：服务状态、近 24 小时崩溃与熔断、磁盘趋势、未收口的行动、组件与链端状态。

生成过程**不经过模型**，每条关注项都带判定依据。没有历史数据就说「首次记录」，不编。报告存文件名不存正文，需要时从 `briefings/` 读，可在线看也可下载 `.md`。

## 四、从处置里学

行动收口时会自动沉淀经验。两条规则，都只补审计**看不见**的东西：

| 规则 | 学到什么 |
|---|---|
| 目标级连败 | 同一服务连续 N 次行动没做成 → 下次先查根因，别原样重来 |
| 用户放弃后接手 | 你取消 AI 的处置、随后自己在同服务上做成 → 下次先问你想怎么做 |

第二条是审计做不到的：它要求「同一个动作先失败后成功」，而你放弃之后往往换了动作，动作名对不上，就永远沉默——而这类事件信息量最大（说明 AI 的判断方向就是错的）。

**三条纪律**：

- 连败按「从最后一次成功往后数」，不是历史累计。按累计算的话，一条经验会在问题修好之后继续告诉模型「这个服务修不好」。
- **「取消」不算「修不好」**。主动取消与超期记「未证明」，不进入任何失败聚合。否则迟早产出一条「这个服务修不好」的假经验，而真相只是你那天没空。
- 经验仍是审计的视图，不是第二个数据库。所以它也会过期——半年前的处置结论，环境早变了。

## 五、成长报表

行动 tab 下方按 ISO 周列出：

| 指标 | 分子 / 分母 |
|---|---|
| 首次解决率 | 无失败步骤即完成 / 收口行动数 |
| 预案命中率 | 套了预案的行动 / 收口行动数 |
| 预案有效率 | 套预案且复验通过 / 套了预案的行动 |
| 用户修正率 | `user_fix` 经验条数 / 收口行动数 |
| 平均步数 | 已落盘步骤 / 收口行动数 |

全部从 `missions.json` / `playbooks.json` / 审计直接算出，不经模型转述——同一个数据集，换个人来算必须得到同一个数。

**分母为 0 显示「—」而不是 0%**。0/0 写成 0% 会被读成「一次都没成」，那是另一回事。样本不足会明说「这个量级只看有没有明显异常，不适合看趋势」，不给一个漂亮的空报表。

## 六、修掉的两个真缺陷

1. **续作上下文断链**：`aiMissionResumeContext` 原来只在「有已完成步骤」时注入，于是巡检 / 晨报 / 守护 / 入站产出的**全新** pending 行动点「继续」时，模型收不到目标，只能反问「你想让我做什么」。改成绑定即注入目标，有步骤才附摘要。

2. **状态机的「报告型」例外**：晨报没有执行阶段，产出那一刻就该完成。原先要么给状态机演戏（先 running 再 done），要么允许 `pending→done`（破红线 1）。最终让例外落在**事实**上：必须已经挂上报告文件名，才允许跳过转移表；没挂报告的行动依旧被挡在门外。

## 七、验证

- `go test ./...` 全绿，`go vet` 干净；`gofmt -l .` 只剩刻意不格式化的 `memory_api.go`
- 新增单测：`playbook_test.go`(9) / `briefing_test.go`(8) / `sediment_test.go`(12) / `growth_test.go`(9)
- 其中三条反向断言值得单独提：取消三次**不**生成「修不好」；成功后连败**清零**；`mission_fix` 与 R1 **不**抢同一个 ID
- `tools/cdp_p2_mission_test.js` 26 条断言全过：预案三态渲染、行动卡片的预案徽标与【写操作】标记、报告弹窗等宽全文、成长五卡（含「—」分支）、周表、无未捕获 JS 异常
- 顺带修了两处**会误报的测试**：端口守卫的绝对阈值（2s）卡在本机单轮快照 1.5–1.8s 上，全量跑必假失败，改成「相对预算的一半」

**没验到的**：评测集新增的 T15「续作不丢上下文」只有静态检查，**没有实跑**（需要真实模型额度与可操作的后端目录）。它不进 A/B 子集，也不影响现有基线。

## 八、这版没做

- 预案全自动沉淀（仍是你点「存为预案」）、预案跨版本迁移、晨报推送
- **项目画像吸收 Mission 历史**：要先定「观察到的事实」与「推断」怎么分层展示，否则会把推测写成登记项——那正是画像分层一直在防的事。留到有真实故障样本再动
