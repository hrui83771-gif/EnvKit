## 一、设置页

此前散落在 `config.json` 里的几十个值，要么只能手改文件、要么改完要重启。现在收敛成一页三区，每个开关改完即生效。

**基础（11 卡）**
安装与分发、网络代理、镜像与校验、项目目录、数据库（只读）、链端（只读）、更新检查、告警与通知、定时行动、界面、能力开关。

**开发者（8 组）**
AI 记忆与摘要（摘要阈值 / 保留量 / 单轮超时 / 单文件读取上限）、数据保留（审计 / 轨迹 / 影子报告 / 行动超期 / 行动保留）、日志配额、控制台端口、启动校验与重试、运行时（只读）、模型兼容性（自动探测）、恢复预算与断路器（含「重置断路器」）。

划线以下这些原本是**写死的常量**，现在改为运行时读取，改完不用重编：

| 常量 | 原值 | 现在 |
|---|---|---|
| 自身日志单文件上限 / 归档份数 | 5 MB / 10 份 | 可调 |
| 业务日志单文件上限 / 归档份数 | 8 MB / 5 份 | 可调 |
| 前端 / 后端启动校验窗口 | 45s / 25s | 可调 |
| 子进程重试次数 / 退避 | 3 次 / 2s | 可调 |
| AI 单文件读取上限 | 64 KB | 可调 |

> 日志配额走 `atomic.Value` 快照，`devSnap()` 不经手——写日志的热路径正持 `logMu`，在它里面去取 `cfgMu` 会锁序反转。

**评测（四档）**
冒烟自检 / 门禁 / 恢复率（沙箱注入）/ 任务评测·A-B，按"越安全越靠前"排序。破坏性档走服务端 428 强制确认，`预演` 只打印将要执行的命令与参数、不真跑。四个脚本的输出经 SSE 按 `scEval` 回流到页面。

**端点切分**
新增 `/api/dev/config`、`/api/alerts/config`、`/api/missions/config`、`/api/update/config`、`/api/notify/config`。都是「指针字段 + 独立端点 + nil-guard merge」——老配置缺这一段就按默认值走，不会被整表单替换冲掉。

## 二、AI：Agent 闭环 Phase 1

- **行动（Mission）** 成为一等实体：目标、状态、断点、触发方式、执行记录各自持久化，`/api/missions` 与 `/api/missions/events` 提供读写与事件流，前端多一个「行动」tab。
- **断点续作**：进程重启后能接着上次的动作往下走，而不是从"你好，有什么可以帮你"重开。
- **触发框架**：定时巡检（默认开，60 分钟一次）、每日晨报（默认 08:30）、外部 HTTP 触发（默认关）。**定时产出只生成"待批行动"，不会自己跑**——真要执行仍需你点继续；会写状态的动作照旧过确认。
- **并发加固**：可崩进程的 map race 全部收掉；判据改为结构化自申报，词表命中降级为兜底。

## 三、自动更新检查

不再是"填个地址、自己维护一个 version.json"：

- 默认地址指向 `https://api.github.com/repos/hrui83771-gif/EnvKit/releases/latest`，**发一个 Release 就等于发布了版本信息**（`tag_name` 当版本号、`body` 当更新说明）。
- 同时兼容自己的 `version.json`（`{"version":"x.y.z","notes":"…"}`），填哪个地址都能用。
- 默认**每 72 小时**复查一次，可填 0–168；填 0 = 只在启动时查一次。`IntervalHours` 用指针区分"没配过"（默认 72）和"显式关掉定时复查"（0）。
- 「忽略版本」只压提示、不压检查——界面上仍然看得到最新是哪个版本，否则用户会以为检查坏了。
- 只提示，不下载、不替换、不自动升级。

## 四、通知与静音

- **全局静音**（默认关）：打开后主动推送全停（Windows 气泡 + Webhook）。只关主动推送，"操作回执"照旧——点了「测试告警」却没反应，会让人以为按钮坏了。
- 「发一条测试告警」绕过静音，标题带时间戳以避开冷却期抑制；没配 Webhook 也会弹气泡。
- 通知出口统一走 `notifyUser()`，散落的 `platform.Notify` 直调只剩操作回执。

## 五、桌宠

- 台词改用**洗牌袋**：整池洗牌依次取，取完再洗，新一轮首句与上轮收尾相同则换位。此前是裸 `Math.random()`，小池子里"老是那几句"的观感就来自这里。
- **天气问候**：开启天气后，开场问候会把天气补在同一句里——"早上好！环境很健康。外面在下雨，伞带上。"。判断顺序是先看天（打雷 → 下雪 → 下雨 → 雾霾）、再看温度（≥35 烤干 / ≥24 舒服 / ≥8 加外套 / <0 零下）、最后看季节反常。首次查询要 1–3 秒，所以问候先开口、天气回来再补全，不阻塞开机。
- 天气仍是**可选能力、默认关闭**，开关只在设置页「能力开关」卡里（个人中心那套入口已删）。
- 鼠标穿透、大小三档、托盘「创建桌面快捷方式」。

## 六、修复

- **CRLF 被当成重绘，整行日志丢失**（`lineWriter`）：`'\r'` 一律清空缓冲，而 Windows 子进程输出几乎全是 CRLF → `Error: xxx` 整行被吞，日志只剩"子进程无任何输出（疑似杀毒软件拦截）"。改成延迟判定：`'\r'` 后看下一个字节是 `\n` 就提交整行，否则才重绘。**此前大部分"零输出"结论都是误判，不是杀软。**
- **npm 解析只验壳不验真身**：`npm.cmd` 只是壳，真身是 `node_modules\npm\bin\npm-cli.js`。原先取 PATH 上第一个存在的 `npm.cmd`，前两个坏了就会"装依赖永远失败、启动却看着能跑"。改为逐个校验真身、跳过坏壳，并把坏目录报给用户。
- **预演结果弹窗没有滚动条、关不掉**：容器 `max-height:82vh + overflow:hidden`，正文既没 `flex` 也没 `overflow`，6000 字输出把页脚推到裁切区外。改为正文自己滚（`flex:1;min-height:0;overflow:auto`）、页脚 `flex:none`，并加宽版 / 等宽 / 点遮罩关闭。
- **全局静音开关方向反了**：开关亮着显示"已静音"，实际通知正常在发。回显与保存都改成 `checked = muted`。
- checkbox 被全局 `input{width:100%}` 拉满、勾选行文字竖排。
- 个人中心「允许查询天气」勾选框错位。

## 七、升级说明

- 构建需要 Go 1.26+；`resource.syso` 已含 3.4.0.0 版本资源。
- `config.json` 新增可选段：`dev`、`update`、`notify`、`alerts`、`pet`、`missions`。旧配置可直接用，缺段即按默认值。
- 老配置里 `update_url` 为空时仍然不检查更新；要开启就在设置页填地址（或直接用新装的 `config.dist.json` 预置值）。
- 新增 `tools/make_dist.py` 打包时自动注入当天 `buildDate`，「关于」和诊断报告不再显示上一个发版日。

## 九、已知限制

- 恢复预算、断路器阈值仍只读，需手改 `config.json`。
- 「无效操作次数 / 验证准确性 / 安全违规率 / 误拒率」四项指标还没有自动产出脚本，评测区只标注口径。
- 入站触发端点（`POST /api/trigger`）没有独立密钥，只沿用本机 token 并服务 `127.0.0.1`，不适合暴露到公网。
- 更新检查只比对版本号，不校验发布包签名。
