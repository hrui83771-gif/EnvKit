# 问题清单可点化 · 待复检 · 新手指引入口（2026-11-07）

> 范围：只改"用户看得到的那一层"，后端只多给结构化动作，不新增任何执行能力。
> 触发：11/07 17:50 的用户视角复盘（"从用户的使用角度还有啥建议"），
> 用户选了其中 1 / 2 / 4 / 5 四条一起做。

## 一句话

系统本来就算好了"下一步该干什么"，但只把它印成一行灰字：
**用户得自己去找那个按钮。** 这一轮把「建议」变成「按钮」，顺手补上
「配置改完状态没跟着走」和「引导入口太深」这两个每天都会撞到的断点。

## 1　问题清单里的建议，现在能点了

**旧**：`#issues-list` 只渲染 `<b>问题</b>` + `<span>建议：…</span>`（`40-ops.js`）。注释里
自己写着"只报问题不给下一步，等于把负担推回给用户"，而给出来的"下一步"还是纯文本。

**新**：`Issue` 多一个 `Acts []string`（`runtime.go`），每条渲染成按钮。格式是
`kind` 或 `kind:arg`，前端白名单解释：

| act | 落地动作 | 复用哪个既有入口 |
|---|---|---|
| `check` | 跑一次检测 | `#btn-check` |
| `install` | 补装缺失组件（幂等） | `#btn-install` |
| `deps:web` / `deps:backend` | 装前端依赖 / 整理后端依赖 | `#btn-web-install` / `#btn-backend-tidy` |
| `dbtest` / `createdb` | 测连接 / 建库 | `#btn-db-test` / `#btn-init-db` |
| `start:<svc>` / `restart:<svc>` | 启动 / 先停再启 | `#btn-<svc>-start`、`stopPost()` + `guardedStart()` |
| `breaker:<svc>` | 复位断路器 | `#btn-sd-breaker` |
| `ports` | 切到启动页并扫端口 | `goto('start')` + `#btn-ps-scan` |
| `goto:<panel>` | 切面板 | `goto()` |
| `focus:<id>` | 切到该控件所在面板、滚动、聚焦、闪一下 | `goto()` + `focus()` + `.flash` |
| `ai` | 把问题与建议填进 AI 输入框（**不发送**） | `aiOpen()` |

**边界（没动的东西）**：不认识的动作返回 `null`，宁可不显示也不猜；所有写操作照旧
走 `askConfirm` / 428 确认卡；权限闸仍在 `aiExecTool` 那一层。act 里**不含**命令、
路径或参数，只是"点页面上哪个按钮"的选择器。

之所以不让前端从 `Action` 的措辞里反推动作：那违反"能用客观事实判就别用措辞判"。

## 2　改完配置，状态不再假装是最新的

**旧**：`saveNow()` 成功后只写三个「已保存」，顶部芯片和检测卡仍挂着上一次检测的结论。
用户改完 MySQL 密码会以为这就好了。

**新**：保存成功 → `markCfgStale(true)`（`20-shell.js`）：

- 顶部四个芯片加 `.stale`（虚线圈边）+ 后缀「· 待复检」；
- 多一条 `#stale-banner`：「配置已保存。下面这些状态还是按旧配置算的，重新检测一次才准。」+「重新检测」按钮；
- 任何一次 `runCheck()`（主按钮 / 复检条 / 后续接进来的触发源）都会清掉它。

**不自动重跑检测**，这是有意的：检测会刷日志、会改桌宠表情，还会让"谁发起了什么"变糊涂。
只把事实摆出来 + 给一键复检。

**结论本身不抹掉**：`chip()` 仍显示上一次检测算出来的真值（"环境 就绪 · 待复检"），
不改成"未检测"——把它抹成未检测等于丢证据。

## 3　失败现场给三个出口

`runtimeIssues` 里服务失败那条现在带 `restart:<svc>` / `ports` / `ai`：
**再试一次 / 看看端口是不是被占 / 把这段错误交给 AI**。

顺手修了一处误导：`phDegraded` 的旧文案让人"点「复验」"，而界面上**没有**这个按钮
（复验是启动流程里的一步）→ 改成"重启一次会重新走复验"，并把重启做成可点的。

桌宠话术同步：`{0} 失败了，点红标看日志` → `{0} 失败了，日志已标红；待处理里可以重试`
（指向真的能动手的地方，而不是让它去猜）。

## 4　引导入口从「关于」搬到个人中心

全项目原本只有「关于」弹窗里一个 `#about-replay`。现在个人中心多一个「新手指引」，
点开同样是 `open('replay')`，点完自动收起面板。

## 判据

`tools/cdp_issues_acts_test.js`（新增，8 条断言，全部真实鼠标 + 真实输入事件）：

1. 空配置下问题清单出现可点按钮
2. 点「去填写」→ 切到 `panel-config` 且 `document.activeElement === #fe_dir`
3. 真输入改库名 → 保存 → `#stale-banner` 可见 + `.chip.stale` = 4
4. 点「重新检测」→ stale 条消失、芯片回到实线
5. 切 EN → 按钮/复检条/芯片三处无中文残留
6. 个人中心「新手指引」点开能起引导层
7a. 13 个合法动作全部有 label，`evil:rm-rf` 必须为 `null`
7b. 「问 AI」把问题与建议填进 `#ai-in`、打开抽屉、**不发请求**

隔离：把 `EnvKit.exe` 复制到 `.gotmp/cdp-issues/` 从零配置跑，不碰真实 `config.json`；
收尾按 PID `/T` 杀进程树（**不按映像名通杀**，那会顺手杀掉用户正在用的实例）。

**变异验证**：把 `saveNow` 里的 `markCfgStale(true)` 删掉 → 3、4 变红、其余仍绿；
复原后 8/8 全绿。

## 没做的

- 问题正文（`what` / `action`）在英文模式下仍是中文——这是存量（UX-2026-11-06 §P2-11），
  含变量的文案得先模板化才能进字典，不在本轮范围。本轮新增的按钮/复检条/芯片都有译文。
- 全链路体检（建议 3）、配置方案切换（建议 6）没做。
