# EnvKit v2.3.0

一次性合并 v2.1 至 v2.3 三个版本的交付。系统从「AI 加一组工具」演进为结构化的
Agent Runtime：主链路 `观察 → 理解 → 计划 → 权限 → 执行 → 验证 → 审计 → 学习`
的每一环都有明确的实现与可验证的产出。

发布日期：2026-10-04

---

## 一句话说明

**执行完成不等于环境恢复。** EnvKit 只承认由客观证据支撑的结论——端口是否监听、
共识视图是否推进、备份是否真能还原，而不是命令的退出码。

---

## 本版新增

### 启动方式不再硬编码（v2.1）

此前前端启动固定执行 `npm run serve`，后端固定 `go run main.go`。项目换成
`npm run dev` 或入口在 `cmd/server/main.go` 时，EnvKit 会直接失败。

现在启动命令从项目自身推断：读取 `package.json` 的 scripts，与安全白名单取交集。
`deploy` / `migrate` / `reset` / `drop` / `build` / `lint` 一律拒绝；无法识别时
**明确拒绝启动并说明原因**，不再静默回退到猜测的命令。后端入口按
`main.go → cmd/*/main.go` 顺序推断，可由用户在配置页覆盖。

实测：`npm run dev` / `serve` / `start` 三类项目均正确识别，危险脚本全部被拒。

### 统一权限裁决（v2.2）

此前「什么算危险」分散在三处判定（AI 工具白名单、HTTP 428 确认、高危红框标记），
换个入口就可能绕过。现收拢为单一裁决器，四档结论：

| 档位 | 行为 |
|---|---|
| `auto` | 只读操作，直接执行 |
| `confirm` | 需用户确认，服务端以 HTTP 428 强制 |
| `elevated` | 高危操作，红色警示样式确认 |
| `forbidden` | 派发前即终止，并告知模型不要重试或绕道 |

**记忆不是权限**：用户记忆与自动经验只影响建议的呈现与排序，不改变任何动作的
权限档位。该约束不依赖提示词自觉——裁决器不读取任何记忆字段，单测构造
「所有写操作都免确认」的极端记忆后，数据库还原与危险脚本仍分别处于最高确认档
与禁止档。

### 任务轨迹（v2.2）

每次任务留下完整过程：计划、动作、证据、复验结论、失败、人工介入、结果。
`trace_id` 零改动贯通至每一条审计记录——现有几十个审计调用点一个都没改。

人工介入的判定刻意严格（四条全过才记）：同一轨迹上下文 + 动作同类 +
AI 此前失败过 + 人工操作成功。误判一次会生成一条持续影响后续所有任务的经验，
**噪声代价远高于漏报**。

### 进程生命周期验证（v2.2）

此前「端口一监听到就立即返回」，而最常见的故障是服务起来几秒后崩溃。现在端口
监听后进入存活观察窗，期间进程消失或端口关闭即判为启动失败，并附日志尾部尾部
12 行作为证据。

实测：构造「启动即崩」场景，正确判为 `crash_after_start` 而非「已就绪」。

### 统一运行时状态源（v2.2）

新增 `/api/runtime/state`，是全系统唯一的状态计算源。每条问题都带**可执行的下一步**
——只说「有问题」不说怎么办，等于把负担推回给用户。

```
[error] 前端依赖未安装（node_modules 缺失） → 先执行 npm install，否则 npm run 必然失败
[warn]  识别不出前端启动脚本（项目类型：react） → 在「程序配置 → 启动方式」手动填写
[warn]  后端进程在运行但未通过复验 → 点「复验」确认；未复验前不要当作已就绪
```

服务状态用五态取代布尔值：**进程在跑但没复验过 = 降级**。布尔值表达不了这个
区别，而这正是「执行不等于成功」在状态灯上的体现。

### 经验与记忆的适用边界（v2.3）

经验现在带**作用域、证据、成败计数、失效判定与置信度**。切换项目后该项目积累的
经验会标记为失效并不再注入，用户可显式标为全局条目跨项目生效。失效是**标记而非
删除**——界面要能解释「为什么这条不生效了」。

环境指纹刻意**不含 IP**：NAT 模式下虚拟机地址每次都变，算进去会让全部经验失效，
失效机制就从信号源退化成噪声源。

### 备份可还原性（v2.3）

此前备份复验只查文件完整性与校验和一致，而**文件没坏不等于能还原**。现在每次
备份后自动跑静态检查（毫秒级），可查出「文件完整但内容缺损」的情况——例如备份
命令误加 `--skip-triggers` 导致触发器全部丢失，此前三项判据全绿。

还原演练（真建临时库导入实测）保留为按需触发：它要建库导数据、耗时几十秒，
不该因为「验证一次备份」就偷偷花掉一分钟。

### 环境符合性检查（v2.3）

此前只报「已安装 v1.23.6」，不报「项目要求 ≥1.25，你这个跑不了」。现在从
`go.mod` 与 `package.json` 的 `engines` 读取要求并比对。

三态严格区分：**项目未声明要求时明说「未声明」，不说「符合」**。只判「够不够用」，
不判「是否完全一致」——要求 1.24 而实际 1.25 是正常的，判成不一致会制造假警报，
直到用户开始无视所有告警。

### 执行计划可见 + 调用预算分级（v2.3）

工具调用轮数上限由固定 8 改为按任务性质分档：常规 4 轮、需要读项目代码 10 轮、
跨子系统分析 16 轮。同时新增执行计划展示——每个工具调用前以自然语言告知用户
正在做什么（「正在搜索 xxx」），任务结束后自动折叠。

预算耗尽时明确告知**发生了什么、可以怎么继续**，而不是静默截断。

### 数据库只读查询（v2.3）

新增 `db_query` 与 `db_list`，AI 可以直接查业务数据做分析。四道安全防线在
MySQL 侧生效：语句首词白名单、强制 LIMIT、会话级 `READ ONLY`、标识符转义。

只读操作不弹确认卡——防线已在数据库侧，给只读操作加确认只会训练用户闭眼点确认。
写操作仍需确认。结果被截断时显式告知模型，避免它以为看到了全部数据。

### 换思路引导（v2.3）

模型在同一动作上连续失败 2 次时，在**执行前**拦截并给出换方向的建议。判定时
区分「换参数」与「重复」——更换搜索关键词是正确做法，不算重复。只对探索类工具
生效：写操作连续失败通常是环境问题，换工具没有意义，该做的是先解决环境。

## 升级说明

从 v2.0.0 升级无需重装环境。配置文件的缺失字段会补默认值，
`config.json` 建议在升级前备份一份。

**新增能力默认状态**：

| 能力 | 默认 | 说明 |
|---|---|---|
| 记忆与经验层 | 关闭 | 在「程序配置 → AI 助手」勾选启用。不启用则不产生经验，也不注入任何记忆 |
| 链端守护 | 关闭 | 沿用原有行为。启用后链端宕机会自动拉起并复验 |
| AI 助手 | 关闭 | 沿用原有行为，需自行配置服务商与密钥 |

所有破坏性操作仍需逐次确认，服务端强制校验，模型无法跳过。

## 已知边界

- **写入能力未验证**：链端复验的判据是「共识视图在推进」，不发送探针交易。
  读能力可确认，写入能力需自行用测试账户验证。
- **经验增益尚无对照数据**：记忆与经验的作用域、置信度、失效机制已实现并有单元
  测试覆盖，但「有经验 vs 无经验」在真实任务上的量化对照尚未完成，计划在后续
  版本以评测集形式给出。
- **链端主机地址会变**：用户的链端运行在本地虚拟机，NAT 模式下地址由 DHCP
  分配。若守护提示「不可达」，先确认虚拟机已启动与地址是否变化——此时自动恢复
  **不会执行**，因为恢复命令本身需要通过 SSH 送达。
