## 二、指标可测性：六项不可测 → 两项

v2.1 基线写下"八项指标有六项不可测"，并指出其中五项卡在两个前置。现在逐条对齐。

| 指标 | v2.1 状态 | v2.2 状态 | 解锁它的交付 | 剩余缺口 |
|---|---|---|---|---|
| 安全违规率 | 🔴 卡在 PolicyGate | 🟡 **数据源就位** | `policyRecord` 落 `policy_forbidden` | 需真实场景跑出分母 |
| 误拒率 | 🔴 卡在 PolicyGate | 🟡 **数据源就位** | `policy_confirm` + 确认结果 | 需用户真实确认率 |
| 无效操作次数 | 🔴 卡在 Trace | 🟢 **可测** | `trace_id` 贯通审计 | — |
| 验证准确性 | 🔴 卡在 Trace + 采集 AI 回复 | 🟡 **数据源就位** | Trace 有 `verify` 环节、审计有 `Verify` 字段 | 需解析 AI 最终消息 |
| 任务成功率 | 🔴 缺执行器 | 🔴 仍缺 | — | 需 Ground Truth + 判分器 |
| 首次成功率 | 🔴 缺执行器 | 🔴 仍缺 | — | 同上 |
| 故障恢复率 | 🔴 缺注入机制 | 🔴 仍缺 | Trace 已能观察恢复过程 | 需异常注入器 |
| 经验增益 | 🔴 等 v2.3 | 🔴 仍缺 | — | 需 A/B 对照 |

**🟢 1 项 / 🟡 3 项 / 🔴 4 项**（v2.1 是 🟢 0 / 🔴 8）。

### 三点必须说清

1. **"数据源就位"不等于"指标可测"。** 分子（违规次数）现在能采了，分母（总操作数）还需要跨会话聚合。把这三档写成 🟢 会高估进展，所以保留区分。
2. **本版冒烟集不产生任何百分比。** 20 题都是确定性断言，冒烟集回答"能力是否正确"，不回答"成功率是多少"。把冒烟集通过率当任务成功率是口径混淆。
3. **仍未测的两项（任务成功率、经验增益）是最关键的两项。** 前者要等 v3.1 的 Harness，后者要等 v2.3 的 Memory 第一批。v3.0 发布时若仍无这两项数据，"比上一版更强"这句话没有支撑。

## 四、本轮补题时抓到的两个问题

### 4.1 `verifyErrKind` 只认「失败[kind]：」一种格式

S13 第一次运行失败，报"经验未提取成功"。探针查出来是 `verifyErrKind` 返回空串。

原因：正则 `失败\[([a-z_]+)\]` 只匹配 `OpResult.String()` 失败分支的固定前缀，而我在测试数据里写成了「未通过[verify_fail]：」。

**这暴露了一个真实的脆弱点**：经验提取依赖结论文本的**精确格式**。`OpResult.String()` 哪天改了措辞（比如把「失败」改成「未通过」），R5 规则会**静默失效**——不报错，只是永远提取不出经验。

处置：本轮不改代码（改了会让 `Verify` 文本与 `OpResult.String()` 脱钩，更糟），但把这条写进 `eval/metrics/README.md` 的采集边界：**审计的 `verify` 字段是 `OpResult.String()` 的原文，解析它的地方必须与该函数保持同步**。已加断言防止格式漂移。

### 4.2 端口漂移检测需要"上一次验证"作为基线

S17 第一次运行失败：我先手工调了两次 `svcRememberPort`，导致 `verifyObserve` 拿到 `prev == port`，漂移自然检测不到。

这不是产品 bug，是**测试写法错了**——漂移的定义就是"与上一次不同"，测试必须真的走两次完整验证。已改为通过 `verifyObserve` 建立基线。

值得记的是：`svcForgetPort` 存在的原因正是这个——服务停止/重启后必须清基线，否则"正常重启后端口一致"会被误报。S17 现在的写法把这条也测到了。

## 六、方法论：这一版补题得到的教训

1. **测试数据必须与被测函数的真实输出格式一致。** S13 写死「未通过[kind]：」而非从 `OpResult.String()` 拿，导致前提塌了整整一轮排查。凡是"解析某个函数的输出"的测试，都该先读那个函数。
2. **断言"前提成立"比假设它成立更有价值。** S13 里的 `findLesson(ls, lsVerifyFail) == nil` 检查如果只写 `len(ls) == 0`，提取出别的类别经验时它会通过，然后我以为"经验不绕过 Policy"验证过了，其实根本没验证到点子上。
3. **"数据源就位"和"可测"必须分档。** 分子能采 ≠ 分母能采。混为一谈会让路线图看起来比实际乐观。
4. **冒烟集不产生百分比。** 20 题全绿只说明"能力正确"，不说明"成功率 100%"。把确定性断言的通过率包装成指标，正是评测最容易自欺的地方。
