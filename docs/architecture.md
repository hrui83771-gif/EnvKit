# EnvKit 架构与文件职责

> README §8 的下沉材料：逐文件职责、关键取舍、以及每条设计约束的**失效场景**。
> 只看概览请回 [README](../README.md)。

---

## 一、四个边界

EnvKit 的全部设计可以还原为四条边界。理解这四条，其余结构都是推论。

| 边界 | 谁来守 | 越界时的后果 |
|---|---|---|
| 模型 → 系统 | 24 个受控工具（无任意命令执行） | 提示注入直接变成系统命令 |
| 动作 → 授权 | `policy.go` 四档裁决 + HTTP 428 确认闸门 | 换个入口即可绕过危险判定 |
| 执行 → 结论 | `verify.go` 三类验证器 | 模型把「命令成功」说成「环境恢复」 |
| 结论 → 记忆 | `scope.go` 作用域 + 置信度 + 失效判定 | 别的项目的经验错套到当前项目 |

## 二、执行与验证

### `verify.go` —— 三类验证器

服务的判据不是「进程在」，而是**端口监听 + 存活观察 + HTTP 握手 + 进程属主匹配**。
最后一项防的是「端口是别人的服务」这种假阳性。

备份的判据分两级，**因为它们回答不同的问题**：

|级别 | 问什么 | 手段 |
|---|---|---|
| 完整性 | 文件有没有坏 / 被改动 | 非空 + **sha256 复算** + 尾部 `dump completed` 标记 + 库名标记 |
| 可还原性 | 能不能真的导回去 | 静态检查（触发器/视图/存储过程/字符集）+ **真实演练**（建临时库导入） |

**文件没坏 ≠ 能还原** —— `--skip-triggers` 生成的备份文件完整、sha256 一致，
但触发器全丢。这类情况静态检查会降级结论，而不会报「已复验通过」。

链端的判据**不是块高**：FISCO-BCOS 2.x 的 PBFT 在无交易时进入心跳态，
空块只共识不落盘（`omitEmptyBlock=true`），空闲链块高 6 秒内 +0 属正常。
主判据是**共识视图推进**，块高只作证据并注明「静止属正常」。

> 拿不到视图时降级用块高，且**不许判失败** —— 分不清空闲与卡死。

### `opresult.go` —— 结果契约

`OpResult{Ok, Verified, Evidence, ErrKind}` 取代裸 `error`。

`Verified` 是三态而非布尔：**失败 / 执行了但没验到 / 已确认恢复**。
把它压成布尔会产生最坏的一类谎报——「已执行、还没确认成功」被说成「已完成」。

`Evidence` 字段是给模型看的：它能引用什么，取决于运行时拿到了什么。

## 三、受控执行

### `policy.go` —— 四档权限裁决

`auto` / `confirm` / `elevated` / `forbidden`。

关键设计：**禁止档在派发前终止**。不是「执行了再拒绝」，
而是根本不发出去。裁决器**不读取任何记忆字段** ——
所以「记忆影响权限」这条路在结构上被堵死，由单测保证。

### `procops` / `program.go` —— 进程生命周期

子进程绑定 Windows Job Object：无论正常退出还是被强杀，整棵服务树都由系统回收。
网页端「退出程序」复制 Job 句柄，避免 `KILL_ON_JOB_CLOSE` 误杀用户自己拉起的服务。

### `chain.go` —— 可达性三态

先探TCP 端口，再谈认证。**主机不可达时绝不触发自动恢复**——
恢复命令靠 SSH 送达，送不到就毫无意义。

（历史事故：守护循环丢弃了 err，虚拟机 IP 一变就无限重启 + 通知轰炸。）

## 四、Agent 运行时

### `ai*.go` —— 工具注册表与确认闸门

OpenAI 兼容任意 baseURL。24 个工具，全部副作用经此发出。

确认机制：需确认的动作以 HTTP 428 由**服务端强制**返回，模型无法跳过。
白名单内的动作在评测里可自动批准，但**永不批准触碰用户数据与进程的操作**。

### `plan.go` / `replan.go` —— 预算与换思路

预算分两级：文本分类给初始预算（只是起点），运行中观察「每轮有无新信息」按事实提额。

**Re-plan 按「工具 + 参数」判定重复** —— 换关键词恰恰是正确做法，
只看工具名会惩罚正确行为。

### `explore.go` —— 文件探索沙箱

根目录白名单=已配置的前后端目录及共同父目录；
黑名单 `node_modules` / `.git` / `dist`；
`config.json` / `.env` / `id_*` / 密钥后缀**拒读**。

限额：深度 3 / 条目 200 / 64KB / 400 行 / 命中 50 / 扫描 5000。
输出套 `<untrusted_data>` 定界符并做密码脱敏，越界落审计。

## 五、记忆与归因

### `scope.go` —— 经验的失效判定

经验带三样东西：**作用域**（项目级 / 全局）、**置信度**、**证据**。

项目目录变了，该项目的经验立即标记失效并停止注入。
这一条听起来是细节，但不做的后果是**把别的项目的经验错套到当前项目**，
而模型无法察觉——它只会认为那是自己知道的事实。

### `trace*.go` —— 任务轨迹

`trace_id` 贯通审计，一次任务的计划 / 动作 / 证据 / 复验 / 人工介入全部留痕。
人工介入单独成环节，因为它决定「这次恢复算不算自主」。

### `audit.go` —— 操作审计流

含执行主体、目标、结果、耗时、复验结论、所属 trace_id，按天分文件保留 30 天。

## 六、数据

### `dbops.go` / `aibackup.go`

备份工具分两个方向，且**边界是硬约定**：

| 工具 | 方向 | 边界 |
|---|---|---|
| `db_backup` | 写 | 需确认 |
| `list_backups` | **只读** | 绝不代替「检查」去创建备份 |

这条边界是 v2.5 评测抓出来的：问「检查备份能不能用」时，
模型**一次工具都没调**就要执行 mysqldump ——
而用户点确认后，一份新备份会覆盖损坏现场，之后再想查「当时坏在哪」就没有证据了。

根因有两层，只修一层不够：预检把「含备份二字」一律判成创建；
更根本的是**模型根本没有「查看现有备份」的工具**。

> **缺能力时模型会拿最像的动作凑，而那个动作恰好有副作用的那个。**

## 七、界面

`web/index.html` 单文件内嵌（含 xterm.js），四个路由各自独立 SSE 日志与状态徽标。

统一运行时状态源是`/api/runtime/state`，前端**不从零开始**，
也不自行推断健康——绿灯的判据是 `phase==running && verified`，
`verified` 缺失按 false处理（显示「未验证」）。

> 绿灯只按 `running` 上色，等于把「执行不等于成功」在视觉上抹掉——
> 那会让前面所有验证层努力在视觉上等于零。
