# EnvKit 审计报告

日期：2026-11-06　范围：**只看 EnvKit**，不含它要部署的 FarmTrace 业务系统；**不含测试 / 评测 / 门禁方向的建议**（按要求排除）。

依据：`envkit/` 源码、README、`docs/architecture.md`、`docs/ROADMAP.md`、`docs/DESIGN-multi-agent.md`、`docs/RELEASE-v3.7.x.md`。所有"缺什么"的判断都先 Grep 过源码，不凭印象。

当前版本 `main.go:29` = **v3.7.3**，最新发布说明 v3.7.2（2026-11-03）。

---

## 一、一句话结论

**EnvKit 不缺功能，缺的是把已有能力连成一条"对外可交付的线"。**

它的工程底座是这个仓库里最扎实的部分：权限裁决、验证器、轨迹、审计、影子事务、配置加密、独立 LAN 口都做成且守住了边界。但它的能力几乎全部作用在**环境层**（进程在不在、端口听不听、DB 连不连得上、链端共识推不推进），对"被部署的那套业务系统到底能不能用"没有判断；同时几个日常高频体验（撤销、设置检索、降级可见）还停在"够用"而不是"好用"。

另一个观察：`ROADMAP.md` 的未偿还项几乎都集中在验证与度量侧，产品化条目散落在各版 RELEASE 说明里，没有一份统一的产品待办。这份报告可以当成产品侧待办的第一次收口。

## 二、现状盘点

### 规模

|---|---|
| 非测试 Go 文件 | 117 个，约 6.7 万行（含测试共 227 个 .go） |
| 内嵌前端 | `web/src/js/` 12 个模块，约 9.7 千行；`index.tpl.html` 里 38 张卡 |
| 受控工具 | 26 个（`ai_tools.go` 注册表；`architecture.md` 记 25 个是旧口径） |
| 拓扑适配 | `topology_registry.go` + `topo_local/topo_db/topo_chain.go` 三适配器 |
| 手机端 | `lan*.go` 13 个文件，独立 18766 端口、12 条接口、默认只读 |
| 文档 | 6 份 DESIGN/架构、9 份 RELEASE、9 份评测基线、1 份 ROADMAP |

### 已经具备的能力（**不要再当新功能提**）

- **主链路**：Go/Node/MySQL 安装与演练安装、程序配置、链端 SSH/内嵌终端/守护、前后端启停与端口诊断
- **执行与验证底座**：`policy.go` 四档权限（`auto/confirm/elevated/forbidden`）+ 428 强制确认、`opresult.go` 三态结果、`verify.go` 三类验证器、审计流 30 天、轨迹与回放、`explore.go` 文件沙箱
- **恢复与自愈**：`guard.go` 确定性守护快路径、`shadow.go` 影子事务与连续 20 次晋升、`txbudget.go` 两层节制（per-target 上限 + 全局动作预算熔断）、`strategy.go` 恢复策略、`trigger.go` 降级挂钩与定时产出
- **Agent 能力**：`plan.go`/`replan.go` 预算与换思路、`ai_mission.go` 断点续作、`playbook.go` 预案库、`lesson.go`/`sediment.go` 经验沉淀、`briefing.go` 晨报、`growth.go` 成长报表、`ai_shadow_intent.go` 影子判定（实验性、默认关、无产品调用点）
- **交付与诊断**：`distexport.go` 运行时一键导出分发包（**带泄漏扫描，命中敏感值即 409 拒绝**）、`diag.go` 一键诊断包（报告 + 脱敏配置 + 日志 + 审计 + state）、`restore_drill.go` 恢复演练、`dist_check.py` 分发校验
- **状态与配置**：`runtime.go` 唯一状态源 `GET /api/runtime/state`（env/project/services/db/chain/issues）、`configwatch.go` fsnotify 热重载、`configschema.go` 配置校验、`projectbrief.go` 项目画像（2 分钟缓存）、DPAPI 加密配置、配置导入导出可脱敏
- **访问与呈现**：控制台硬绑 `127.0.0.1` + sameOrigin + token；手机端独立端口/独立路由表/配对码/TOTP/Host 白名单/能力分档默认；桌宠 + 天气（默认关）、托盘、中英 i18n、SSE 日志分区、三态徽章、Markdown/表格/代码高亮
- **其它**：`winevents.go` Windows 事件日志、`av.go` Defender 白名单、`update_config.go` 自动更新、`localdev.go` 本地开发支持

### 边界（必须原样保留）

四档权限 + 428 在执行层收口；**不提供任意命令执行**；文件探索限项目目录；记忆/置信度永远不是权限来源；SSH TOFU 指纹；控制台与手机端口物理分离；**只有天气出网**，新增外连默认关 + 白名单。

### 路线图里明确不做（`ROADMAP.md §6.1`、`DESIGN-multi-agent.md §八`）

自建 LLM、通用工作流引擎、**多项目 / 多环境编排（当前是单项目本地工具）**、自动修改用户配置（除非显式确认且可回滚）、把记忆做成权限来源、采集文件内容与凭据；多 Agent 阶段 4（多用户/权限、预案全自动沉淀与执行）明确不做。

## 四、按重要性排序的建议

### A 级：结构性，最该先动

**A1. 执行生命周期与串行锁**（已在设计里，**待评审**，我建议提前）

`DESIGN-multi-agent.md §一` 自己列了三个客观瓶颈：`aiChatMu.TryLock()` 全局串行（只读任务也得排队、手机端和桌面抢一把锁）、`aiRunLoop` 直接写 `http.ResponseWriter`（关掉页面任务就没了，Mission 断点续作只是补救）、单循环过载。阶段 2「后台 worker + 结果订阅端点」和阶段 3「同一时刻一个写执行体 + 有上限的只读并发」都还挂在"待评审、不承诺版本号"。

我的判断：**这两项比阶段 1 的角色化更该先做**。角色化是锦上添花，执行生命周期决定了 EnvKit 能不能从"打开浏览器才能用的助手"变成"常驻托盘的服务台"——README 里已经把它定位成常驻服务台了，实现却还绑在 HTTP 请求上。改动时必须同步 `DESIGN-agent-loop.md` 红线 5/7，前台后台共用一把锁的语义要重写。

**A2. 业务语义层健康探针**（现有验证器最自然的延伸）

现在 `runtimeServices()` 只有 web / backend 两个，`runtimeIssues()` 判的是环境、项目目录、版本符合性、端口、DB 连通、链端活性——全是**环境层**。ROADMAP §2.5 的健康检查矩阵也止步于此。

结果是：业务后端端口在听、DB 连得上，但业务接口全 500、上链不可用、IPFS daemon 没起来，EnvKit 依然显示一片绿。建议让被托管项目自己声明一个探针契约（例如 `GET /api/health` 返回 db / chain / storage 三态 + 版本号），EnvKit 把它接进 `runtimeIssues()` 的 `project` 分区，输出沿用现有的 `what + action` 结构。

这不需要 EnvKit 理解业务，只需要一个可配置的 URL + 字段映射；也正好把「执行完成 ≠ 任务完成」这条原则从环境层推到业务层。**注意别做成自动修**：探针只报状态，动作仍走现有确认闸。

**A3. 非任务型降级统一可见**

验证器结论层的降级做得很好（`degraded` 相位、证据强度变弱都明说），漏的是**能力型降级**：`getlantern/systray` 初始化失败时库只打日志不返错，`registerSystray` 直接 return、不调 `Ready()`，托盘和菜单全无，而 EnvKit 自己完全感知不到，控制台照常跑——用户只能对着一条 `Unspecified error` 猜。

建议做一个轻量的「能力就绪表」：托盘、天气上游、更新检查、手机端口、 Defender 白名单这些"挂了不影响主流程"的能力，各自有就绪状态，失败时在设置页或状态中心显式写「不可用 + 影响什么 + 怎么办」，而不是只在日志里留一行。托盘可顺带加一次重试（A3 是唯一能直接兑现 11/6 systray 诊断遗留项的改动）。

**A4. 状态中心补证据链**

`Issue` 现在是 `level / scope / what / action`。`action` 给的是"该做什么"，但没给"凭什么这么说"。EnvKit 最强调证据，用户看到的却只有结论。建议逐条带上触发判据（哪个探测值、阈值、观测时间），让 `what` 可点开看成因。这条不新增数据，只把已有的探测过程暴露出来。

### B 级：产品化新功能

| # | 建议 | 现状依据 | 边界 |
|---|---|---|---|
| B1 | **通用操作撤销** | `20-shell.js:36` 明写「目前只给清空对话的撤销用」，10 秒窗口；`10-i18n.js` 里到处是「不可恢复」 | 覆盖删除行动、清理已收口、配置改动这类轻量写；**备份覆盖库、白名单等破坏性操作不进撤销**，保持 428 |
| B2 | **设置页搜索 / 命令面板** | 设置一页三区（基础 11 卡 / 开发者 8 组 / 评测四档），模板里 38 张卡，找一个旋钮要滚很久 | 纯前端索引，不碰后端；顺带把常用动作做成 `Ctrl+K` 直达 |
| B3 | **配置模板 / 档案快照**（换口径） | `state.go:41` 的 `Projects` 是单套；README 已有「配置导入导出（可脱敏）」 | **不做运行时多套并存**（撞 §6.1）。只做"存一份命名快照 + 一键切换前预览 diff + 可回滚"，本质还是单项目工具。若确要多套并存，先修订 ROADMAP 红线，别偷偷做 |
| B4 | **项目代码里的硬编码凭据只读扫描** | `distexport.go` 只扫自身 exe 里有没有混入 config 值；被托管项目源码里的明文口令 / API Key 没人管 | 只读、只给清单和迁移建议，**绝不自动改代码 / 配置**（§6.1 + 用户偏好）；要落地修改一律走确认卡，且只提供"改成引用环境变量"这一条建议动作，不引入任意编辑 |
| B5 | **手机端在只读之外放开「审批」** | `lanapi.go` 明确手机端只读、AI 只看得见非写工具，是刻意收紧 | 手机端能"批准 / 拒绝桌面发起的确认卡"，但不能发起写工具。审批仍回桌面执行层 `aiExecTool` 过闸；这样人在外面也能放行一次备份，不必回家 |
| B6 | **分发包 / 诊断包补业务侧快照** | 两个包现在装的是 EnvKit 自己的状态 | 把 A2 的业务健康结论、区块高度、表数、脱敏后的版本号一起带上，交付时才有"这套环境真能跑"的证据 |

### C 级：体验与长期

1. **托盘恢复**：systray 失败后可在设置页手动重试一次，不必重启整个程序（配合 A3）。
2. **通知分级与静默时段**：现在只有"全局静音"一个总闸；按级别（链端不可达 / 巡检报告 / 桌宠问候）分时静默更实用。
3. **可访问性**：桌宠状态、进度环、三态徽章目前靠颜色和动画，补 `aria-label` / 文本状态；`50-pet.js` 每次切态已经清 `bubble.textContent`，基础在。
4. **i18n 覆盖补齐**：改文案要同步 `tools/i18n_en.json` + `i18n_build.py`，历史存量还有未译条目，日常维护成本高，可做一次收口。

## 五、不碰的东西

- 四档权限裁决与 428 强制确认——所有新能力都在执行层 `aiExecTool` 之下；B5 的手机审批只做"放行"，不做"代执行"。
- **不引入任意命令执行**；A2 的探针是固定 URL + 固定字段映射，不接受用户输入拼命令/任意地址。
- 不改「单项目本地工具」红线；B3 只做快照，不做多套运行时编排。
- 不把记忆、经验置信度、影子判定结果当权限来源。
- 新增外连默认关 + 白名单；探针目标地址要进配置并走现有白名单机制。
- 不做 AI 侧全自动自愈、预案全自动执行（`DESIGN-multi-agent.md §八`）。

---

## 六、如果只做三件

1. **A2 业务语义层健康探针** —— 把 EnvKit 最核心的"验证器决定结论"从环境层推到业务层，是它区别于普通部署脚本的关键。
2. **A1 后台执行 + 重写锁语义** —— 让"常驻托盘服务台"这个定位名副其实；设计文档已写好，缺的是排期。
3. **B1 + B2 日常体验两件套** —— 成本最低、每天都会用到，比再加一个 AI 能力更能改变使用感受。

A3（托盘降级可见）体量很小，建议顺手带上，正好把 11/6 那次 systray 诊断的遗留项兑现。
