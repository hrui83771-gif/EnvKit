**手机能管这台机器了：独立局域网端口 + 扫码配对，看屏幕、通剪贴板、开本机与链端终端；附带修掉「复验通过但 AI 说报错」。**

发布日期：2026-11-01
产物：`EnvKit.exe`（__EXE_MB__ MB，单文件）
SHA256：`__EXE_SHA__`
分发包：`EnvKit-v3.7.0-win64.zip`（__ZIP_MB__ MB）

## 一、手机访问：另开一个端口，而不是把主端口放开

主控制台的三道闸一条都没动：`main.go` 硬绑 `127.0.0.1`、`sameOrigin()` 只认回环、`serveIndex` 把当前令牌明文注入首页且 `/` 不过鉴权中间件。手机要连进来，做法是**另起一个 `net.Listener`（默认 18766）+ 独立的 `ServeMux`**：

| 项 | 主控制台 | 手机端口 |
|---|---|---|
| 绑定 | `127.0.0.1` 硬编码 | 本机局域网地址 |
| 路由数 | 一百多个 | **12 条** |
| 鉴权 | 首页注入的 `X-EnvKit-Token` | 每台设备一个令牌，`HttpOnly` cookie |
| 桌面路由 | 全在 | **根本不存在**（404，不是"被判断成不允许"） |

「不存在」和「被拦住」是两件事。前者的攻击面是 12 个 handler，后者是 100 个 handler 加 100 处判断；判断是可以写错的，不存在不会。

其余边界：

- **Host 白名单**防 DNS rebinding。判据不是 `Origin == Host`——rebinding 下手套域名两者本来就一致——而是 Host 必须是本机名字或本机网卡地址。
- **配对**：控制台生成 6 位配对码（或密码），磁盘只存 sha256；同一 IP 连错 5 次锁 10 分钟；设备 24 小时 TTL。
- **可选 TOTP**：配对时再加一道 6 位动态验证码（30s 一步，允许 ±1 步），`otpauth://` 二维码直接扫进验证器。同一时间步内的重放会被拒。
- **防火墙**是手机连不上的头号原因，而这从来不是 EnvKit 的锅。所以给了诊断 + 一键放行：**只放行手机端口，绝不放行控制台端口**——那个端口的三道闸依赖"只有本机能连"这个前提。读不到防火墙状态时明说"读不到"，不报"被拦"。

## 二、三个「碰本机」的能力，分档默认

手机能看状态、点启停、和 AI 对话是 v3.7 之前就有的事。这一版加了三个直接碰这台电脑的能力，每一个都单独开关、单独端点、单独审计：

| 能力 | 默认 | 为什么是这个档 |
|---|---|---|
| 看屏幕（截图 / 最多 2560 宽） | **开** | 只读，不改变任何东西 |
| 剪贴板读写（纯文本，64KB 上限） | **关** | 剪贴板是隐私密度最高的地方：密码、token、验证码都从这里过 |
| 本机 PowerShell / 链端 SSH 终端 | **关** | 执行类。链端通常有 sudo，能登上去的话本机的闸都不再是障碍，所以两者共用同一个开关，不给人"链端更安全"的错觉 |

实现上没有引入重依赖，三个库都在百 KB 级：`kbinani/screenshot`（GDI 截屏）、`atotto/clipboard`（纯 Win32，不起子进程）、`UserExistsError/conpty`（Windows 10 1809+ 伪控制台）。图像缩放没有引 `golang.org/x/image`——它会强推 `x/text` 到 v0.43，而本项目锁在 v0.37.0（已发布 exe 的哈希依赖它）。改用自己写的 30 行面积平均重采样。

能力开关的判断顺序是**先鉴权、再看开关**。反过来会让未配对设备探到"这台机器开了哪些能力"。

## 三、手机端界面

- **右上角折叠栏，三区**：① 终端 & 剪贴板 ② 主操作（全部启停 / 刷新 / 截屏）③ 日志报告。默认只展开第一区。
- **截图点击放大**：卡片里是 1280 宽的缩略图（省流量），点开取的是 2560 那张。双指 pinch、单指平移、双击 1x↔2.5x。没让浏览器自己 pinch——那会缩放整个页面布局，退出后顶栏和按钮还是错位的。
- **保存到手机**：放大层右上角「保存」。手机上把一张图弄进相册没有统一做法，按能力从强到弱试三条路：Web Share（iOS Safari / Android Chrome 都认 file，分享面板里就有「存储图像」）→ `a[download]` + blob → 明说「长按图片保存」。Blob 在点击的**同一个同步帧**里用 canvas 做出来：Safari 只认 transient activation，`await fetch` 之后再调 `navigator.share` 会被拒。
- **日志报告区**：24 小时统计（操作数 / 失败数 / 复验通过数 / 高频动作）、最近一份晨报（读已落盘的那份，**不现场生成**——看一眼的请求不该有副作用）、实时日志（可切分区，`[FAIL]`/`[WARN]` 高亮）。日志走 AI 用的同一个 `aiGetLogs`，不另写一份切片。
- 手机页的 xterm.js 从**手机端口自己的 `/xterm/*` 路由**按需加载：主控制台的资源在这个端口上不存在，这是刻意的边界。

## 四、修：「复验通过，AI 却说报错」

这是个真 bug，三处叠在一起，全部可对照源码验证：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `ai_tools.go` `svcAIView` | 自己拼状态（`running` + `ever_verified`），没走 `runtimeService()`。界面读五态 `phase`，AI 读另一套 → 同一个服务两处读数 |
| 2 | `program.go` 幂等跳过 | 写的是 `setProg(key, false, res.Verified, …)`。未复验时 `Verified=false`，`setProg` 直接落 **progFail**——"服务明明在跑"被记成"启动失败" |
| 3 | `verify.go` `endStartFlag` | 守卫 `!ps.Running → return`。第 2 步把 Running 置 false 之后，**紧接着那次真正通过的复验结论被丢掉**，红字留在状态里 |

复现路径：首次启动慢（首次编译超过 45 秒的校验窗口）→ 复验没通过 → 再点一次启动 → 命中幂等跳过 → 状态写成失败 → 这次编译完了、复验其实通过 → 但结论进不来。**界面绿、状态红、AI 复述红。**

改法：幂等跳过单独走 `progSetSkip`（ok / warn / fail 三态，"已在运行"不再等于"失败"）；`endStartFlag` 只在用户主动停止时保留旧值，其余一律以后到的复验为准；AI 快照的 `phase` 直接取 `runtimeService`，`what_to_do` 按 phase 分支（running 时明确写"状态正常，不要报告故障"）；`recent_errors` 包上"这些是历史行，不代表当前状态"——模型会把没有时间过滤的旧 `[FAIL]` 当现状念出来。

## 五、过程中被自己的测试抓到的三个问题

1. **ConPTY 双次关闭 → 进程堆损坏消失。** 第一版终端代码写完，手机开终端再断开，整个 EnvKit 进程直接没了，退出码 `3221226356`（`0xC0000374`），日志在"本地终端已关闭"处无声断掉。写了个复现脚本开终端→断开→轮询 `/api/health`，发现断开后 0.5 秒进程就没了。根因：`p.Close()` 被调了两次（循环末尾一次 + `defer` 一次），Windows 回收句柄号后第二次 close 打在别人的对象上。改成 `sync.Once` 包一层，全流程只留一个关闭点，且在等输出 goroutine 之前关。
2. **能力键名混用。** 抽屉里那块判断写的是 `caps[termKind]`，而 `termKind` 是 `local`，服务端 caps 的键是 `term` → 打开本地终端那一刻就被 3 秒轮询判成"电脑端已关闭"，自己收掉。当时"标题对了""抽屉关了""xterm 挂上了"全绿，只有"终端层显示了"是红的。断言分得细才看得出来。
3. **放大层背景写成了半透明**（`rgba(…,.97)`），底下手机页的"服务 / 前端 / 后端"透上来形成重影。截图取证时才看见。

## 六、升级说明

直接覆盖 `EnvKit.exe` 即可，配置与数据（`config.json` / `missions.json` / `playbooks.json` / `memories.json` / 审计）都在 exe 同目录，不受影响。

三点需要注意：

- `config.json` 新增可选段 `lan`（`enabled` / `port` / `devices` / `require_otp` / `otp_secret` / `allow_shot` / `allow_clip` / `allow_term`）。旧配置可直接用，手机访问默认**关**。
- 打开手机访问需要在同一个局域网内；Windows 防火墙可能拦（见上文的一键放行）。手机端口只放行它自己，不要让"顺便把控制台也放行"这种建议出现。
- 终端依赖 ConPTY（Windows 10 1809+）。老系统上开关会显示不可用，不会给你一个点了没反应的按钮。
