# EnvKit v3.6.0

**修三个「它自己说错了话」的 bug：记忆说没有、预案删不掉、只读检查被判失败。**

发布日期：2026-10-30
产物：`EnvKit.exe`（11.91 MB，单文件）
SHA256：`cd251ef6c38616f17372335db42ce251dd574798f08be74b4d79582c7c775d51`
分发包：`EnvKit-v3.6.0-win64.zip`（5.17 MB）
SHA256：`3c7103761763aa1d407ab53527de204e28ddba226415dbc3ea525be5b3076839`

这一版**没有新功能**。三个都是已交付能力在自己身上出错：能力在，但它报出来的结论是错的。其中第三个会把「首次解决率」这类指标算成 0——指标本身没错，是喂给它的判据错了。

---

## 一、记忆：明明记得，却说「没有」

问 AI「你记得什么」，它回答「当前没有记忆条目」，而记忆列表是空的——但记忆文件里其实有东西。

原因：`manage_memories(op=list)` 复用了注入视图 `memoriesFor("")`，那个函数回答的是「**这一轮会注入什么**」，不是「**一共有哪些**」。空任务时只有「每轮注入」的条目会被算进去，标「仅相关时注入」的条目被当成不存在。

现在列表读全量视图，逐条标 `★`（每轮都注入）/ `·`（仅任务相关时注入），并给出「本轮未注入」的原因。同时把按钮文案从状态词改成动作词：「设为每轮注入」/「改为按需注入」——原来亮着开关其实是「按需」，点一下反而把自己静音了。

**这类错误最伤**：它不是答不出来，是把对的说成错的。

## 二、预案：点了「删除」没反应

从 AI 侧的「行动」tab 点删除预案，确认框弹出来了——但它整个压在 AI 侧栏**下面**，确认按钮正好落在侧栏区域，真实鼠标点中的是侧栏。所以后端连请求都没收到。

`z-index` 顺序已固定并写进注释：header 5 < 菜单 40/60 < `.modal` 80 < toast 95 < 桌宠右键 999。

顺带修了两处：删除失败时不再静默（异常回落原生 `confirm` + toast）；「存为预案」加了去重——连点两下不再产生两条标题、步骤、统计完全一样的预案（删掉一条另一条还在，看起来就像「删除不生效」）。

回归测试补了**遮挡断言**：用 `elementFromPoint` 查确认按钮那个坐标上真正是谁。CDP 的 `element.click()` 会绕过命中测试，所以以前 31 条 DOM 断言全绿，用户还是点不到。这条断言先红后绿验证过。

## 三、只读检查：一步成功，却被判失败

本机 `missions.json` 里的真实记录：

```
goal: 检查数据库    state: failed
msg : 回合结束但没有复验证据
step: db_check  ok=true  证据「连接成功：127.0.0.1:3306，MySQL 8.0.40，目标库已存在」
```

一步成功、什么都没改，却落 `failed`。因为收口只认 `verify_result`，而「检查数据库」既没有状态可复验（没改任何东西），也不属于报告型（只有巡检/晨报按「产出即完成」判）。

一条记录难看是小事，污染面是大的：首次解决率的分母、R6 连败规则、预案命中率全都被它带偏。成长页显示一排 0，不是系统不行，是判据把成功算成了失败。

**修法**：给「纯只读行动」一条与报告型并列的合法完成路径，判据仍然是客观事实（红线 1 没有放宽）：

- 每一步都成功（落盘记录里的 `ok`，来自工具执行结果，不是模型自述）；
- 每一步用的工具都在注册表里**且不是写工具**；
- 注册表里查不到的工具名一律按「写」处理——证明不了它没动东西，就不给它免复验。

有写操作的行动仍然一律 `failed`：重启了服务却没复验，本来就该是失败。失败提示也补了一句「有写操作的行动须调用 verify_environment 复验」，让下一个人知道卡在哪。

单测覆盖五格：只读全成功 → done、只读有一步失败 → failed、只读 + 有写操作 → failed、一步没跑 → failed、未知工具名 → failed。

## 四、升级说明

直接覆盖 `EnvKit.exe` 即可，配置与数据（`config.json` / `missions.json` / `playbooks.json` / `memories.json` / 审计）都在 exe 同目录，不受影响。

**已判 failed 的历史只读行动不会追溯改判**——它们是按当时的判据落盘的记录，改历史等于篡改审计。
